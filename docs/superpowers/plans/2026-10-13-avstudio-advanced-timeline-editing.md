# AVStudio Advanced Timeline Editing Implementation Plan

> **For agentic workers:** After separate implementation approval, use `superpowers:executing-plans` to execute these checkbox steps inline. The user prohibits subagents and delegation. Requesting approval does not authorize implementation.

**Goal:** Render the exact edited Video 1/Video 2 replacement sequence, separate overlays, and editable non-looping music as H.264/AAC MP4 while retaining current working editing and delivery features.

**Architecture:** Extend the existing immutable occurrence snapshots and external source registry. Pure frontend operations/projectors and a backend authoritative interval planner share the approved timing rules; FFmpeg normalizes video edits, selects picture/original PCM together, composites existing overlays, then mixes explicit music segments. Keep the legacy request/render branch compatible.

**Tech Stack:** Existing React/TypeScript/Vite, Vitest/Testing Library, Python/FastAPI/pytest, FFmpeg/FFprobe, and Playwright with installed Edge. No dependency, package, lockfile, or configuration changes.

**Spec:** [Approved design](../specs/2026-10-13-avstudio-advanced-timeline-editing-design.md), read in full before execution. The user's 2026-10-13 approval authorizes this plan document only; the specification's earlier pending status text does not revoke that approval.

## Global constraints

- This planning task creates only `docs/superpowers/plans/2026-10-13-avstudio-advanced-timeline-editing.md`. All application/test changes described below are future work requiring implementation approval.
- No installation, package/lock/configuration edits, system settings, commit, push, deployment, or subagents. All automatic repository mutation steps are omitted; working-tree checkpoints are read-only.
- Video 1 is contiguous and determines N/F. Video 2 is full-screen, multiple non-overlapping placements, and replaces picture **and original audio** in its range. No hidden-base-audio fallback.
- Source trims and existing overlay schedules remain inclusive; new project/content intervals are half-open. `L=max(1,floor((selectedSourceFrames/sourceFPS/speed)*F+0.5))`. F is 24/25/30/50/60; K=48000/F. Speeds remain 1/0.75/0.5.
- New editor requests use schema version 2, deduplicated main/replacement source uploads, and explicit music segments. Missing schema version/version 1 retains existing payload, audio looping, and rendering behavior. Unknown versions fail.
- Keep separate PIP/image slots, image above PIP, and `eof_action=pass:repeatlast=0:shortest=0`; PIP disappears at source EOF, never freezes, and supplies no audio.
- One active music source; positioned non-overlapping segments; same-track ripple delete; final partial frame padding less than K samples; silence at gaps/EOF; music tails truncate at N. No automatic looping in version 2.
- Keep 30 history entries, metadata-only snapshots, retained File identities, guarded tokens, preview/commit/cancel transactions, existing Video 1 import/speed rebasing, image/PIP-range exclusions, and completed-project editing lock.
- Output stays 1280×720 SDR CFR H.264/yuv420p, medium/CRF 23, stereo 48 kHz AAC/192k MP4 with faststart. No MOV export, transitions, database/auth, deployment, collaboration, persistence, added track types, audio audition, waveforms, limiting, or unrelated refactoring.

## Review focus

These five risks receive explicit tests in the owning tasks:

1. Auto FPS changes after reorder/import or an empty base must convert positioned content consistently across retained history, or reject atomically (Tasks 2–3).
2. A candidate becomes ready after Undo, a newer file choice, or render locking; it must never reinstall stale media (Tasks 3 and 8).
3. Base deletion leaves a replacement outside N: it must stay visible, restorable and repairable, blocking render without silent clipping (Tasks 2, 3, 9–10).
4. Browser-estimated song duration differs from decoded EOF: less-than-K terminal padding is permitted, larger exhaustion rejects before queueing (Tasks 5 and 7).
5. Split halves share a source but different normalized windows; deleting one must retain exact other-half content and resource ownership (Tasks 2, 3, 6, 11).
